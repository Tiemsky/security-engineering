# Contract compatibility and migration rules
- Every event carries `schema_version` (SemVer). Current: **1.1.0** (1.0.0 events remain valid). Schemas are `additionalProperties: false`; framework-specific data goes in `extensions`.
- **PATCH**: clarifications/description changes, no validation change.
- **MINOR**: new *optional* fields, new enum values appended. Producers on 1.x remain valid for consumers on 1.y (y ≥ x) that ignore unknown enum values.
- **MAJOR**: removed/renamed/required fields, narrowed types. Requires a migration note here, dual-emit period of ≥ 1 minor release of the installer, and test fixtures for both versions.
- Consumers MUST reject events whose MAJOR is higher than supported and SHOULD tolerate higher MINOR.
- Timestamps UTC `Z`. IPs: IPv4 dotted or IPv6 RFC 5952 text; aggregate IPv6 by /64 for rate/blocks (`ip_prefix64`).
- Forbidden content (all events): passwords, OTPs, raw access/refresh tokens, cookies, Authorization headers, API secrets, payment credentials, complete sensitive bodies. Enforced by `policies/redaction.yaml` + tests.
- Validator subset used by tests (`tests/lib/minischema.py`): type, enum, const, required, properties, additionalProperties, items, minItems, minProperties, pattern, min/maxLength, minimum/maximum, format (date-time, ipv4, ipv6), anyOf, $ref. CI additionally validates schemas with the full `jsonschema` library.
## Migration log
- 1.0.0 — initial.
- 1.1.0 (MINOR) — `schema_version` now matches `^1\.\d+\.\d+$` (was const 1.0.0); `response_outcome.status` gains `pending_approval` (decision awaits a human; nothing executed) and `skipped_exception` (allowlisted). Producers emitting 1.0.0 stay valid.
- Assessment documents (`assessment-scope.schema.json`, `assessment-report.schema.json`) are *not* runtime events: they have no event envelope and their own `schema_version` (pattern `^1\.\d+\.\d+$`). Cross-field rules (e.g. "PASS needs evidence") live in `scripts/assessment-gate.py`, not in the schema.
- `assessment-scope.schema.json` 1.1.0 (MINOR) — adds optional `target.target_identity` (`docker_verification`, `container_name_patterns`), used by `scripts/pentest-runner.py` to verify the live target's port is actually published by a container matching the project before any module runs (never infers identity from the port number alone). 1.0.0 scope files remain valid; the check degrades to `not_configured` when the field is absent. `assessment-report.schema.json` stays 1.0.0.
- `assessment-report.schema.json` 1.1.0 (MINOR) — adds optional per-finding fields, all additive (every 1.0.0 report stays valid): `id` (stable identifier), `asset` (affected asset), `finding_class` (`code_audit`/`deployed_application`/`runtime_event`/`admin_audit`), `tool` (`{name, version}`), `timestamp`, `execution` (execution state kept separate from the `result` verdict: `completed`/`error`/`timeout`/`skipped`/`not_run`), `reproduction` (steps), `severity_rationale`, `confidence_rationale`, `applicable_environments`, `review` (`{status, reviewer, at}` human-review status), `remediation_status`, `retest_status`. Two cross-field rules in `scripts/assessment-gate.py` fire only when the new fields are present, so old reports are unaffected: `execution` `error`/`timeout` cannot be a `PASS`; `remediation_status: fixed` contradicts `retest_status: failed`.
