# Generic runtime contract (for new frameworks — see skill `framework-adapter-development`)
An adapter must: (1) resolve client IP only through trusted proxies (IPv4/IPv6, /64 aggregation); (2) emit `http_access` with the route **template**; (3) apply `policies/redaction.yaml` before any sink; (4) never let sink/store failures alter the response (fail-open, except credential limiters); (5) feed the deterministic engine and persist decisions + outcomes with idempotency keys; (6) enforce only active, unexpired scopes; (7) pass `tests/fixtures/scenarios/*.json` with results identical to Laravel and NestJS (`tests/integration/compare.py`).
Engine semantics (reference: `laravel/src/DecisionEngine.php`, `nestjs/src/decision-engine.ts`): window counters per rule+group → threshold/min_distinct → exceptions (allowlist, shared-IP ⇒ manual_review) → evidence minimum → approval gates → mode (observe⇒would_act, alert⇒alert, enforce⇒act+TTL) → idempotency key `rule:version:scope_kind:scope_value:window_start` → outcome (applied | skipped_observe_only | skipped_duplicate | failed | expired | rolled_back).

## Hardened semantics (v0.1.0 validation, Phase D) — every adapter must reproduce these (scenarios in `tests/fixtures/scenarios/`)
- **Input validation**: a signal must be an object with a known `kind` and non-empty string (or integer) required fields ≤ 256 bytes, no control characters, valid IP (zone ids like `fe80::1%eth0` are invalid). Otherwise it is rejected, counted, never reaches a rule; one `system_health` (detector/degraded) event per reason per 60 s.
- **Executable set**: only `observe, alert, rate_limit, temp_ip_block, manual_review` ever run. `account_lock`, `session_revocation`, `challenge` (and anything unknown) ⇒ `decision: manual_review`, `requires_approval: true`, outcome `pending_approval`; nothing becomes active. The executor re-checks and refuses.
- **Statuses**: would_act⇒`skipped_observe_only`, manual_review⇒`pending_approval`, suppressed_exception⇒`skipped_exception`, act⇒`applied|failed`.
- **Idempotency**: key `rule:version:scope_kind:scope_value:window_start`. Duplicates emit ONE `skipped_duplicate` notice per key, then are counted silently (no log amplification). Keys expire with their window.
- **Failure & retry**: a `failed` action releases its key so the next qualifying signal retries it, at most 3 attempts per key, then it gives up (further signals = duplicates). Failed actions leave no partial state (`active` is written only on success). Detector/store errors fail open (traffic is never blocked because of them).
- **Rollback**: `rollback(kind,value)` removes an active action and emits `rolled_back`; idempotent (unknown scope ⇒ nothing). The key stays consumed for that window: a rolled-back scope is not re-blocked until the next window.
- **Time**: an action is active iff `expires_at > now` (inactive exactly at expiry); window membership is `ts > now - window_seconds` (exclusive at the edge).
- **Memory**: per-key window lists capped at 10 000 entries; `sweep()` prunes windows, idempotency keys and shared-IP records; `stats()` exposes sizes.
- **Observability must not break callers**: sink exceptions are swallowed and counted (`dropped`).
- **Redaction vs enforcement**: events are redacted, enforcement state is keyed on the RAW scope (two PAN-like ids stay separate). Callers should still pass opaque identifiers; redaction is a safety net.
- **Not provided in v0.1.0**: shared/distributed state (Redis) and background workers. State is per-process memory, so multi-instance deployments see per-instance counters, and a restart loses windows and active blocks.
